# WhaleYing Benchmark Lab — 开发规范

## 项目原则

以下四项原则长期有效：

- **最小化**：只引入当前实际需要的代码、依赖和结构，不为未来可能的需求提前建设。
- **可复现**：实验和构建过程必须可在同等环境下重复执行并得到一致结果。
- **可验证**：每项评测结论必须有可追溯的数据支撑，不接受无来源的断言。
- **低成本**：在满足正确性的前提下，优先选择轻量方案，减少不必要的基础设施复杂度（包括 API 额度——能用申请额度就不用自费）。

## 技术栈（已按前身项目实际落地）

| 用途 | 工具 |
|------|------|
| 编程语言 | Python 3.14 系列（已核实 3.14.0；统一 `py -3.14`） |
| 包管理 | `py -3.14 -m pip`（不引入 uv） |
| 代码检查 | 自研 `lint_code.py` |
| 测试 | 脚本 + 手动核验（暂不引入 pytest） |
| 配置/密钥 | API 密钥等统一从 `.env` 读取（`.env` 是唯一来源）；用 `load_dotenv(override=True)` 显式加载以确保 `.env` 优先、不被系统环境变量覆盖；**建仓库第一件事先写 `.gitignore` 排除 `.env`，再 `git add`，`.env` 不得入库**；示例配置只用 `.env.example`（不含真实密钥），程序不得在 `.env` 缺失时静默回退系统环境变量 |
| 模型调用 | deepseek-flash / gpt-4o-mini（OpenAI 兼容端点）；qwen2.5-coder:3b/7b/1.5b（Ollama 本地） |

## 文件与目录命名

- 目录名：小写字母 + 下划线（`benchmark_runner`）
- Python 文件：小写字母 + 下划线（`memory_eval.py`）
- 实验配置：`<实验名>_config.yaml`
- 结果文件：`<实验名>_<YYYY-MM-DD>_results.json`

## 代码规范

- 公开接口、核心评测逻辑及复杂函数应提供必要的类型注解和说明；简单、局部、语义明确的辅助函数不强制要求完整 docstring。
- 模块拆分依据职责单一性、可测试性和可维护性判断，不得仅为满足行数限制而拆分。
- 不引入未声明依赖；依赖须在文档中列出。
- 不在代码中硬编码模型名称、API Key 或路径；使用配置文件或环境变量。

## 模型名称规范

实验配置与结果中，模型必须记录**精确标识**，禁止只写简称：

- 云端：API 提供方 + 模型 ID（如 `openai:gpt-4o-mini`、`deepseek:deepseek-flash`）。
- 本地：Ollama 模型名 + 摘要（如 `qwen2.5-coder:3b` + Ollama digest/参数）。

这样将来才能确认实验到底用了哪个模型版本。

## 提交规范

格式：`<类型>(<范围>): <简短描述>`

| 类型 | 适用场景 |
|------|----------|
| `feat` | 新增功能或评测能力 |
| `fix` | 修复错误 |
| `exp` | 新增或更新实验 |
| `data` | 数据集变更 |
| `docs` | 文档变更 |
| `refactor` | 重构（不改变行为） |
| `chore` | 构建、依赖等杂项 |

示例：`exp(mh262k): 3b 无记忆直测 ×3，均值 0%`

## 禁止事项

- 不得创建 Hooks、自定义 Agents、数据库或额外基础设施，除非经用户明确批准。
- 不得运行安装命令（`pip install`、`uv sync` 等），除非经用户明确批准。
- 不得自动生成测试文件，除非用户明确要求。
- 不得在未读取现有文件内容的情况下覆盖文件。
- 不得未经实际运行就上报/标注实验分数。
