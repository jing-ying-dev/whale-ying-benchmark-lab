# WhaleYing Benchmark Lab — 项目概览

## 项目定位

WhaleYing Benchmark Lab 是一个独立新建的跨模型评测框架，核心研究问题为：

> **同一套外部记忆增强组件能否跨模型迁移，并在不同能力水平的模型上产生可测量的性能增益？**

即：把「记忆层（抽取→存储→检索）+ SRL 拆题 + 单跳作答」作为一个可复用的外部组件，挂到不同能力水平的模型（本地 qwen 1.5b/3b/7b，云端 gpt-4o-mini、deepseek-flash）上，量化它对每个模型的增益，并观察增益是否随模型能力变化。

> ⚠️ 当前模型清单只能支持「跨这几个模型迁移」的结论，**尚不足以支撑「对任意模型都成立」的普遍性断言**。普遍性结论须待覆盖更多模型、更多能力层级后再下。

本项目拥有独立的 Git 仓库和开发历史，不直接继承前身项目的 Git 历史；允许在遵守原许可证及归属要求的前提下复用其已开源代码、组件和实验基础。

## 与 Kiroween 2026 的关系

本项目当前以 Kiroween 2026「Frankenstein」类别为落地场景（我们自己的设计解读：缝合记忆层 + 弱模型 = 比各自都强的怪物；非官方规则原文）。展示性对照：本地 3b 在 262k 多跳上**无记忆直测 0%（3 次全 0）→ 装记忆层 + 拆题流程后 47%（3 次全 47）**，+47pp。⚠️ 该 +47pp 是**展示性对照、非单变量受控实验**（两者均为本项目新跑、尚未入库，且配置不同：0% 是直测截断 16k、47% 是有记忆 SRL 拆题+逐跳），**不得作为增益估计引用**。外部事实（Frankenstein 类别、4000 额度、12/1 截止）来源：活动信息 https://kiro.dev/events/、参赛规则 https://kiroween.devpost.com/rules/（2026-11-24 查阅）。

但比赛只是**阶段性落地**，不是项目唯一目标。比赛结束后，本项目的长期定位仍是「跨模型记忆增强评测」，不随比赛结束而失去研究意义。

## 核心评测方向

- **记忆检索评测**：单跳 / 多跳事实问答（factconsolidation，MemoryAgentBench），衡量记忆层对召回与推理的提升。
- **跨模型适配**：同一套记忆层 × 不同模型（本地 qwen2.5-coder 1.5b/3b/7b，云端 gpt-4o-mini、deepseek-flash），看「换模型掉不掉分」。
- **组件消融**：有无记忆层、有无向量 RRF、抽取模型、拆题模型，逐组件量化贡献度。

## 技术栈

技术栈与模型名称规范见 `conventions.md`（每轮常驻，不在此重复）。唯一补充：检索默认**多字段 BM25**；向量+RRF 见下方「组件消融」的限定结论、保留为可拆卸组件。

## 组件消融的已有结论（限定表述）

在当前 factconsolidation 测试配置中，已进行「向量 + RRF」消融，**暂未观察到明确的成绩增益**。因此默认采用 BM25-only，并**保留向量检索作为可拆卸组件**，以便后续在其他数据集或配置中重新验证。

> 该结论仅适用于已测试的数据集、模型、配置和评分条件，不推广为「向量检索本身无价值」。

### 成果归属原则

1. **独立新建**：本项目拥有独立的 Git 仓库和开发历史，不直接继承前身项目的 Git 历史。
2. **合法复用**：允许在遵守 Apache License 2.0 归属要求的前提下引用前身项目中已开源的代码、组件或实验基础，每处复用须在代码注释或文档中明确标注来源。
3. **严格区分成果边界**：既有代码、既有实验数据（WhaleYing-Memory 仓库已提交的历史结果）与本次新增成果（本项目期间新跑、尚未入库的结果，如 SRL 拆题后的 3b 有记忆 47%、3b 无记忆直测 0%）须严格区分并标注来源。**具体哪些已入库、哪些未入库，以仓库实际提交为准，不得凭印象臆断。**
4. **禁止误归**：不得将旧项目的既有成果描述为本次比赛或本项目期间新开发的成果。
5. **实验可追溯性**：每项实验必须记录所用模型及版本、配置、数据集版本、运行次数和评分结果。既有实验结果不得冒充本项目新运行的实验结果；未经实际运行的数据不得标记为实测结果。
