# WhaleYing Benchmark Lab — 研究流程规范

## 适用范围

本文件规范评测实验的设计、执行、记录和报告流程，在涉及以下工作时手动引入：

- 新建或修改评测实验
- 消融测试设计与执行
- 实验结果的整理、对比或报告

---

## 实验设计要求

在实验开始前，须明确记录以下内容：

| 记录项 | 说明 |
|--------|------|
| 实验目的 | 本次实验要回答的具体问题 |
| 实验假设 | 预期的方向性结论（可为空，但须说明原因） |
| 目标变量 | 本次实验改变的变量 |
| 评价指标 | 使用哪些指标、如何计算、数值越高/越低表示越好 |

**消融实验原则**：每次消融原则上只改变一个目标组件。若因工程原因必须同时变更多项，须在实验记录中说明原因并标注结论的局限性。

**对照组一致性**：对比组之间须保持以下条件一致：数据集版本、题目范围、评分标准、模型配置。无法保持一致的条件须在实验记录中明确列出，并说明对结论的潜在影响。

---

## 实验可追溯性要求

每项实验必须记录以下信息，缺失任意一项则该实验结果不得作为有效数据引用：

| 记录项 | 说明 |
|--------|------|
| 模型名称及版本 | 例如 `gpt-4o-2024-05-13`，不接受模糊的 `gpt-4` |
| 实验配置 | 温度、上下文窗口、提示模板版本等影响输出的参数 |
| 数据集名称及版本 | 包括来源、版本号或 commit hash |
| 运行次数 | 单次运行须注明；多次运行须保留每次运行的原始分数，不得仅保存均值和方差 |
| 评分结果 | 原始分数及评价指标名称、计算方式、优劣方向，不得仅报告结论而省略数值 |
| 运行日期 | 实验实际执行的日期，格式 `YYYY-MM-DD`；逐次运行建议记录完整时间戳及时区信息 |
| 执行人 | 谁运行了该实验 |

---

## 成果来源区分

实验结果必须明确标注其来源类别，不得混淆。允许值为以下三项之一：

- **`new`**：本项目期间新运行的实验，须满足上方全部可追溯性要求。
- **`inherited`**：来自 WhaleYing-Memory 或其他前身项目的既有实验结果，须注明原始来源和版本。
- **`reproduced`**：在本项目环境中重新运行了前身项目的实验，须同时保留原始结果和本次复现结果，并说明环境差异。复现实验应尽可能使用原始实验的模型、配置、数据集和评分标准；无法一致时须记录差异，不得将复现结果直接视为原实验结果。

**禁止**将 `inherited` 结果以任何形式描述或呈现为 `new` 结果。

---

## 消融实验命名规范

消融实验名称格式：`<基础系统>_ablate_<被移除组件>_<版本>`

示例：
- `memory_retriever_ablate_reranker_v1`
- `fact_reasoner_ablate_external_kb_v2`

每组消融实验须包含：
1. 完整系统的基线结果（`baseline`）
2. 移除目标组件后的结果（`ablated`）
3. 两组结果的差值及百分比变化

---

## 数据集管理

- **大型数据集、受许可证限制的数据或不适合公开的数据**不得直接提交到 Git 仓库，须记录获取方式、版本信息和校验值（优先使用 SHA256；MD5 可作为一般完整性检查的辅助记录）。
- 小型测试数据可根据许可证和用途合理管理，但同样须记录数据集版本及校验信息（优先 SHA256）。
- 若使用前身项目的数据集，须在实验记录中注明来源为 WhaleYing-Memory，并核实许可证是否允许该用途。
- 数据集的预处理脚本须版本化管理，确保可从原始数据复现处理结果。

---

## 统计报告规范

- 多次运行时，须同时报告均值及方差或标准差，并保留逐次运行的原始分数。
- 若计算置信区间，须注明计算方法（如 bootstrapping、t 分布等）和置信水平（如 95%）。
- 样本量不足时不得夸大统计证据；结论的置信程度须与实际运行次数相符。

---

## 结果文件规范

结果文件命名：`<实验名>_<YYYY-MM-DD>_results.json`

结果文件最小必要字段示意（具体 JSON Schema 待确认，不得提前创建或实现）：

```
experiment_id        实验唯一标识
source               来源类别，允许值：new | inherited | reproduced
model                模型名称
model_version        模型版本
dataset              数据集名称
dataset_version      数据集版本或 commit hash
config_ref           配置文件引用
runs                 运行次数
run_results          逐次运行的原始分数及时间戳列表
scores               汇总分数（均值、方差或标准差等）
metrics              评价指标说明（名称、计算方式、优劣方向）
timestamp            实验日期，格式 YYYY-MM-DD
notes                备注
```

---

## 禁止事项

- 未经实际运行，不得将数据标记为实测结果。
- 不得修改已归档的历史实验结果文件；如需修订，须新建版本并注明修订原因。
- 多次运行时，不得丢弃逐次运行的原始分数，只保存汇总统计。
- 不得在报告中省略评价指标的计算方式和优劣方向。
